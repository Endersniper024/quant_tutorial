# 04 · 回测引擎原理

这是整个项目最核心的一篇。读懂这里，你就理解了"回测"到底在做什么、以及它为什么可信。

对应代码：`quant/backtest/engine.py`、`account.py`、`broker.py`

---

## 1. 回测到底是什么

**回测 = 把策略放回历史里，按时间顺序一天天重演，看它会做出什么交易、最终赚还是亏。**

它本质上是一个"时间机器"，但有一条铁律：

> **在重演到第 t 天时，策略只能用第 t 天及之前的信息。**

违反这条铁律，就是"未来函数 / 前视偏差"，回测结果会好得离谱、却完全不可信。我们的引擎从机制上保证不会违反它。

---

## 2. 两种回测方式：向量化 vs 事件驱动

| | 向量化（vectorized） | 事件驱动（event-driven） |
|---|---|---|
| 做法 | 用 pandas/numpy 一次性算完所有信号 | 写循环，一根 bar 一根 bar 推进 |
| 速度 | 快 | 慢 |
| 直观度 | 抽象，容易不小心引用未来 | 和真实交易顺序一致，直观 |
| 适合 | 大规模筛选、熟手 | 学原理、贴近实盘、新手 |

本框架用**事件驱动**：虽然慢，但它和真实交易"只能基于已发生的事做决策"的逻辑完全一致，新手最不容易写出 bug。

---

## 3. 主循环：三步走

`engine.py` 的 `run()` 就是一个 for 循环，对每根 bar `i` 做三件事：

```python
for i in range(len(data)):
    # ① 撮合"上一根 bar"排队的订单，用"本根 bar 开盘价"成交
    if self.pending:
        prev_close = closes[i-1] if i > 0 else opens[i]
        for order in self.pending:
            trade = self.broker.execute(order, self.account, opens[i], prev_close, date)
            ...
        self.pending.clear()

    # ② 把数据切到"截止本根 bar 收盘"，交给策略决策（策略可能下新单进队列）
    ctx.history = data.iloc[: i + 1]
    self.strategy.on_bar(ctx)

    # ③ 用收盘价结算当日权益，并解冻 T+1 持仓
    self.account.settle(date, closes[i])
```

记住这三步的顺序：**先成交昨天的单 → 再让策略看今天 → 最后结算今天**。

## 4. 为什么订单要"延迟到下一根 bar 开盘"成交？

这是新手最容易犯的作弊，也是本框架最重要的设计。

设想一个错误做法：策略在第 t 天**收盘后**看到 close，然后"以这个 close 价成交"。问题是：**你看到收盘价时，今天已经收盘了，根本买不进这个价！** 这等于用了一个你实际拿不到的价格，回测会虚高。

正确做法（本框架的做法）：
- 策略在第 t 天用 close 做决策，下的单进入"待成交队列"。
- 这笔单在**第 t+1 天的开盘价**才真正成交。

这才符合现实：你晚上想好明天要买，第二天开盘下单成交。代价是最后一天下的单不会成交（数据到头了）——这是合理的、诚实的。

```
第 t 天:  策略看到 close_t  →  下单(排队)
第 t+1 天: 用 open_{t+1} 成交  ← 这才是你真能拿到的价
```

> 📖 这不是我们的发明，而是成熟框架的共识。例如
> [backtrader 官方文档](https://www.backtrader.com/docu/)的 `cheat-on-close` 选项
> **默认就是 False**——含义正是"用收盘信号、下一根 bar 才成交"，和我们这里一模一样。
> 框架对照见 [`08-参考资料.md`](08-参考资料.md)。

## 5. 账户与 T+1：钱和股是怎么记的

`account.py` 用几个数字记账：

- `cash`：可用现金
- `volume`：总持仓股数
- `available`：**可卖**股数（T+1 的关键）
- `cost`：持仓平均成本

T+1 的实现非常直白：
- 买入成交时，`volume` 增加，但 `available` **不变**（今天买的不能卖）。
- 每天收盘 `settle()` 时，执行 `available = volume`（**解冻**：到了第二天，昨天买的就能卖了）。
- 卖出时检查 `available`，只能卖可卖的部分。

每天 `settle()` 还会记一条权益快照（现金+市值），所有快照连起来就是**资金曲线**。

## 6. 撮合与 A 股规则：订单怎么成交

`broker.py` 负责把订单变成成交，并施加 A 股规则：

**涨跌停**（相对前一天收盘价 `prev_close`）：
```python
limit_up   = round(prev_close * 1.10, 2)   # 涨停价
limit_down = round(prev_close * 0.90, 2)   # 跌停价
```
- 开盘价已到涨停 → **买单不成交**（一字涨停买不进）。
- 开盘价已到跌停 → **卖单不成交**（一字跌停卖不出）。

**费用**：
- 买入：佣金 = max(成交额 × 万3, 5 元)
- 卖出：佣金 + 印花税(成交额 × 0.05%)

**整手 & 资金约束**：
- 买入股数向下取整到 100 的倍数。
- 现金不够买期望股数时，自动往下减到买得起的整手数（`_affordable_shares`）。

**滑点**：可选，用一个比例近似真实成交价的偏差（默认 0）。

> 这些规则就是教程 02 提到的"游戏规则"落到代码的地方。它们让回测从"理想世界"
> 回到"真实 A 股"，结果会更可信（通常也更难看）。

## 7. 自己验证引擎没作弊

理解一个系统的最好方式是验证它。试试：
- 打印 `result.trades_df`，检查是否有"当天买当天卖"（不该出现，T+1 禁止）。
- 检查每笔买入股数是否都是 100 的倍数。
- 把某天改成一字涨停，确认那天的买单确实没成交。
